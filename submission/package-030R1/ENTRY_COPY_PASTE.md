# Project name
Antigense Daisy

# Short description
A hardware-first incident cockpit that traces a controlled worker fault through security scans, GPU-backed analysis and database reconciliation, with recomputable custody checkpoints and preserved failures.

# What we built (under 1,500 characters)
Antigense Daisy makes an AI workflow incident inspectable from the device outward. A controlled software fault corrupts a worker result; an integrity check detects it, and a teaching fixture reproduces an unsafe authorization fallback. Semgrep identifies the fallback. A pinned repair rejects unauthorized requests while preserving healthy authorized work.

ClickHouse Cloud preserved 11 incident checkpoints through replayed insertion and exact readback; the query took 160.7 ms. Each checkpoint carries an FCO address and ordered Merkle/MMR commitment. Browser and Python verifiers recompute recorded commitments.

In a separate Akash Console execution lane, the agent created a GPU deployment, selected a lease, loaded qwen2.5:0.5b and received schema-valid security advice in 3.47 seconds. The close request returned HTTP 200 and success:true. All 11 custody leaves verify. Advice was not applied automatically; GPU attestation and final closed-state readback remain unverified. Earlier failures remain preserved.

ChatGPT/OpenAI orchestrates; Claude executes an independent lane. Semgrep, Akash and ClickHouse are used; Pi is excluded. Local OS polling is live; the public site replays evidence. This is a software-injected fault. Cost savings remain unmeasured. Credentials and proprietary internals stay private; original explanatory content carries CC BY-NC-ND 4.0 notices.
